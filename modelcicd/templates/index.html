What this is

A self-hosted tool that continuously discovers, benchmarks, and lets you approve which LLM your application actually uses — separately, for each specific feature that calls one. It doesn't look for "the best model" in general; it finds the best model for one job, tested against that job's own test cases and scored against a rubric written for that job.

from modelcicd.resolver import resolve
model = resolve("support_bot_reply", fallback="gpt-4o-mini")

Why people use it

  • New, cheaper, or better models ship every few weeks — nobody manually re-checks, so most teams either overpay or never find out something better exists.
  • A quality regression from a model swap is usually invisible until a user hits it.
  • "Why are we using this model" is usually answered from memory, not evidence.
  • A silent model swap in production is a real risk — it should require the same sign-off a dependency upgrade would get.

What value it adds

  • Lower cost without guessing — every candidate is filtered by your price ceiling before anything is spent.
  • Quality protected, not just cost — nothing gets proposed without first being scored, blind, against the rubric that feature's own owner wrote.
  • A record that survives memory — every run, candidate, score, and approval is saved with a timestamp.
  • One decision point — a human sees the evidence and clicks Approve; nothing changes silently.

How to use it — from here

  1. + New Project above — connect an application (optionally with its repo, for scanning and later patching).
  2. Scan the repo for AI features already in the code, or add one by hand — a guided form, no YAML to write.
  3. Run the bench (the only step that spends money — it shows the cost and asks first).
  4. Review the leaderboard and click Approve on whichever candidate should go to production. Nothing switches on its own.
