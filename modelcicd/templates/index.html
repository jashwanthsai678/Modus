About Modus — what it does, and why

Continuously discovers, benchmarks, and lets you approve which LLM your application actually uses — separately, for each feature that calls one. Not "the best model" in general: the best model for one job, tested against that job's own test cases, scored against a rubric written for that job.

Your integration point, in full
from modelcicd.resolver import resolve
model = resolve("support_bot_reply", fallback="gpt-4o-mini")
Ranked within price tiers

A cheap candidate only competes against other cheap candidates — "good enough for 10× less" stays a visible, defensible answer, not a guess.

Quality gated first

Nothing is proposed without first being scored, blind, against the rubric that feature's own owner wrote.

Proof, not memory

Every run, candidate, score, and approval is saved with a timestamp and the judge's stated reasoning — "why are we using this model" has an answer besides someone's recollection.

One decision point

A human sees the evidence and clicks Approve. A silent model swap gets the same sign-off a dependency upgrade would.

Getting started

  1. Connect an application — optionally with its repo, for scanning and later patching.
  2. Find its AI features — scan the repo, or add one by hand through a guided form. No YAML to write.
  3. Run the bench — the only step that spends money, and it shows the cost and asks first.
  4. Review and approve — the leaderboard shows every candidate's real answer and score. Nothing switches on its own.

Prefer the CLI?

Every action above has an equivalent command — same tool, same files, either door always leaves the other consistent.
